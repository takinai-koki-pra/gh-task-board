# データモデルと設計思想

Task Board は「人は雑に書き、構造は AI が付け、エージェントも同じ場所に読み書きする」ための個人用タスクボードである。
この文書は、その前提で **タスクをどう表現し、GitHub 側にどう持つか** を定める。UI はこの文書に従属する。

## 1. 設計思想（AI ネイティブの要件）

1. **入力は非構造、保存は構造。** メモ・メール・Slack をそのまま投げれば、タイトル・案件・期限・列が付いた状態で保存される。
2. **正本はエージェントが読み書きできる場所にある。** GitHub Issues を正本にする。API・permalink・コメント履歴が揃い、sweep-slack / sweep-mail / manage-task-board が直接書ける。
3. **タスクは「次に動く主体」を持つ。** 自分 / 相手待ち / エージェント実行可。カンバンの列とは独立した軸。
4. **文脈リンクを必ず持つ。** Slack permalink、メール、元メモ。後からエージェントに「これをやって」と言える材料になる。
5. **時間の軸を持つ。** 期限と再浮上日。今日関係ないものは見えないことで軽くなる。
6. **エージェントの作業結果は Issue のコメントに残る。** 人の操作もエージェントの操作も同じ履歴に並ぶ。取り消せる、監査できる。
7. **一覧を読むのは AI、人は Top 3 だけ見る。** 朝の「今日はこの 3 つ」をボードから生成する。

## 2. 変えないと決めたこと（非目標）

- **階層は 2 段まで。** Issue とチェックリスト。エピック・親子 Issue・サブ Issue は使わない。
- **列は状態、ラベルは属性。** 列は Backlog / Todo / Doing / Done の 4 つから増やさない。
- **正本はあくまで GitHub。** ボードは view であり、消えても困らない。
- **GitHub Projects v2 のカスタムフィールドは使わない。** GraphQL 依存が重く、ボードと密結合になる。全情報が Issue にあるので、必要になれば後から Projects v2 を上に載せられる。
- **優先度は 2 値。** `priority:high` があるか無いか。3 段階以上は使われなくなる。

## 3. タスク = 1 Issue

リポジトリ: `takinai-koki-pra/tasks`（private）。

| フィールド | 置き場 | 形 | 備考 |
|---|---|---|---|
| id | Issue 番号 | `#12` | |
| title | Issue タイトル | 動詞で終わる自然な日本語、40 字以内 | 案件名の接頭辞は付けない（案件はラベル） |
| 列（状態） | `state` + `status:*` ラベル | 下表 | |
| 完了の種類 | closed の `state_reason` | `completed` / `not_planned` | 「やらないと決めた」を Done に混ぜない |
| 案件 | ラベル `client:<slug>` | 複数可 | |
| 次に動く主体 | ラベル `waiting` / `agent` | 排他。無ければ自分 | |
| 優先度 | ラベル `priority:high` | 有無のみ | |
| 場所・文脈 | ラベル `ctx:<slug>` | 複数可 | 例: `ctx:pc2` |
| 期限 | 本文メタ `due` | `YYYY-MM-DD` | 日付はラベルにできない |
| 再浮上日 | 本文メタ `wake` | `YYYY-MM-DD` | それまで Today ビューに出さない |
| 元の文脈 | 本文メタ `source` | URL（複数行可） | 重複判定キーでもある |
| 小項目 | 本文のチェックリスト | `- [ ] …` | GitHub がそのまま描画。進捗は本文から数える |
| メモ | 本文の残り | 自由記述 Markdown | |
| 履歴 | Issue コメント | 人もエージェントも同じ場所 | 本文を書き換えて履歴を消さない |

### 列とラベル・state の対応

| 列 | state | ラベル |
|---|---|---|
| Backlog | open | `status:*` 無し |
| Todo | open | `status:todo` |
| Doing | open | `status:doing` |
| Done | closed | `status:*` 無し（クローズ時に外す） |

## 4. ラベルの名前空間

| 接頭辞 | 値 | 排他 | 色 | 意味 |
|---|---|---|---|---|
| `status:` | `todo` `doing` | 排他 | 青 `2563eb` / 琥珀 `d97706` | 列 |
| `client:` | `dbj` `shinetsu` `jica` … | 複数可 | 緑 `16a34a` | 案件・顧客 |
| `priority:` | `high` | | 赤 `dc2626` | 優先 |
| （接頭辞なし） | `waiting` | 排他（`agent` と） | 灰 `9ca3af` | 相手待ち。自分は動けない |
| （接頭辞なし） | `agent` | 排他（`waiting` と） | 紫 `7c3aed` | エージェントが実行できる |
| `ctx:` | `pc2` … | 複数可 | 灰 `6b7280` | 場所・環境などの文脈 |

- 存在しないラベルは、アプリとエージェントが初回に自動作成する。
- 新しい接頭辞を増やす前に「本文メタで足りないか」「そもそも要るか」を問う。

## 5. 本文の形

本文の先頭に `task` を言語指定にしたコードブロックを 1 つ置き、その下は通常の Markdown。

````markdown
```task
due: 2026-09-19
wake:
source: https://pragmateches.slack.com/archives/C0XXXX/p1700000000000000
```
- [ ] メールルール整理（特に SharePoint 周り）
- [ ] 今週分利用
- [ ] 目視確認

山田さんに確認してから着手。
````

規則:

- コードブロックにする理由: GitHub 上で行が段落に潰れない、正規表現で確実に切り出せる、LLM に出力させやすい。
- キーは `due` `wake` `source` の 3 つから始める。値が無いキーは空のまま残してよい（人が後から埋めやすい）。
- `source` は複数行書いてよい（1 行 1 URL）。
- `task` ブロックが無い Issue も正常。全メタが未設定として扱う。
- 本文メタは人とエージェントのどちらが上書きしてもよい。判断や作業結果はコメントに書く。

パーサの仕様（アプリ・エージェント共通）:

```
^```task\n(?<meta>[\s\S]*?)\n```\n?   … 本文先頭のみ。key: value 行を読む。未知のキーは保持する
```

## 6. 保存しない（計算で出す）もの

| ビュー | 条件 |
|---|---|
| Today | open ∧ (`wake` 未設定 or `wake` ≤ 今日) ∧ ¬`waiting` ∧ (`status:doing` ∨ `due` ≤ 今日 ∨ `priority:high`) |
| 相手待ち | open ∧ `waiting` |
| エージェント待ち行列 | open ∧ `agent` |
| 期限切れ | open ∧ `due` < 今日 |
| チェックリスト進捗 | 本文の `- [x]` / `- [ ]` を数える |

## 7. エージェントとの取り決め

1. **起票時は `source` を必ず入れる。** 同じ `source` を持つ open Issue があれば起票せず、その Issue にコメントを追記する（manage-task-board の Link ベース重複判定と同じ）。
2. **状態の変更はラベルと state だけで行う。** 本文の書き換えは `task` ブロックのメタとチェックリストに限る。
3. **作業の着手・結果・判断はコメントに書く。** 本文の自由記述部分は人のメモ領域として扱う。
4. **`agent` ラベルの扱い。** 着手時にコメントを書き、完了時に結果コメントと共に `agent` を外す。列は人が動かす（エージェントは Done にしない）。
5. **完了の理由を区別する。** やり終えたら `completed`、やらないと決めたら `not_planned` でクローズする。

## 8. 取り込み（まとめて追加）の変換規則

貼り付けたテキストから上のモデルへ写す際の規則。Gemini のプロンプトとスキーマはこれに従う。

| テキストの要素 | 変換先 |
|---|---|
| 見出し行（案件名・プロジェクト名） | 配下の行に引き継ぎ、`client:` ラベル |
| 動ける行（動詞を含む・依頼） | 1 Issue |
| インデントの深い小項目 | チェックリスト |
| 「いまやってること」「対応中」「調査中」 | `status:doing` |
| 「時間があるときに」「いつか」 | Backlog |
| ★・急ぎ・至急 | `priority:high` |
| 「〜待ち」「〜対応中（他者）」「返ってきたら」 | `waiting` |
| 「2台目」などの場所 | `ctx:` ラベル |
| 「金曜まで」「9/19」など | `due` |
| URL・permalink | `source` |
| 挨拶・雑談・事実の記述 | 捨てる |

## 9. 例

```
title:  PC 内フォルダ・ルールを整理する
state:  open
labels: priority:high
body:
  ```task
  due:
  wake:
  source:
  ```
  - [ ] メールルール整理（特に SharePoint 周り）
  - [ ] 今週分利用
  - [ ] 目視確認
```

`status:*` が無いので Backlog に置かれ、`priority:high` により Today ビューに出る。今は見たくないなら `wake: 2026-09-22` を書けば来週まで消える。
